# 01. 프로젝트 구조와 첫 API

- 날짜: 2026-08-07
- 관련 커밋: `6b36198`

## 무엇을 만들었나

Nest CLI로 NestJS 프로젝트를 초기화하고, `GET /` 요청에 문자열을 응답하는 기본 API를 실행했다.

## 왜 필요했나

기능을 만들기 전에 **요청이 어디로 들어와서 어디로 나가는지** 전체 경로를 먼저 봐야 했다.
이 경로를 모르면 나중에 파일을 어디에 만들어야 할지 매번 헷갈린다.

## 핵심 개념 — 내 말로 다시 쓰기

### 요청이 흐르는 경로

```text
main.ts          앱을 만들고 3000번 포트에서 켠다
  → AppModule    어떤 컨트롤러와 서비스가 있는지 Nest에게 알려주는 명단
  → AppController  HTTP 요청을 받는 창구. 어떤 URL을 누가 처리할지 정함
  → AppService     실제 일을 하는 곳
```

핵심은 **컨트롤러와 서비스의 역할이 다르다**는 것이다.
컨트롤러는 "HTTP 세계"의 일(URL, 상태 코드, 요청 본문 파싱)만 하고,
서비스는 HTTP를 전혀 모른 채 비즈니스 로직만 한다.
이렇게 나눠두면 나중에 같은 로직을 HTTP가 아닌 다른 경로(스케줄러, CLI 등)에서도 쓸 수 있다.

### 데코레이터(`@Controller`, `@Get`, `@Injectable`)

`@`로 시작하는 문법. 클래스나 메서드에 **"부가 정보(메타데이터)를 붙이는 표시"** 다.

```ts
@Controller()          // 이 클래스는 컨트롤러다
export class AppController {
  @Get()               // 이 메서드는 GET 요청을 처리한다
  getHello(): string { ... }
}
```

중요한 점: 데코레이터는 코드를 **직접 실행하지 않는다.** 정보를 붙여둘 뿐이다.
그 정보를 읽어서 실제로 라우팅을 구성하는 건 NestJS다.

### 의존성 주입 (Dependency Injection, DI)

컨트롤러가 서비스를 `new`로 직접 만들지 않는다.

```ts
export class AppController {
  constructor(private readonly appService: AppService) {}
  //          ^^^ Nest가 알아서 AppService를 만들어서 넣어준다
}
```

왜 이렇게 하나?

- 서비스를 만드는 방법이 바뀌어도(예: DB 연결이 필요해져도) 컨트롤러 코드는 그대로다
- 테스트할 때 진짜 서비스 대신 **가짜 서비스**를 넣을 수 있다
- 같은 서비스 인스턴스를 여러 곳에서 공유할 수 있다

`@Injectable()`은 "이 클래스는 Nest가 만들어서 남에게 주입해도 되는 것"이라는 표시다.

### 모듈(`@Module`)의 네 칸

```ts
@Module({
  imports: [],       // 다른 모듈의 기능을 빌려올 때
  controllers: [],   // 이 모듈이 가진 HTTP 창구
  providers: [],     // 이 모듈이 가진 서비스들
  exports: [],       // 내 서비스를 다른 모듈에게 빌려줄 때
})
```

Nest는 이 명단을 보고 무엇을 만들어야 할지 안다.
**명단에 없으면 Nest는 그 클래스의 존재를 모른다** — 나중에 "provider를 찾을 수 없다"는
에러가 나면 대부분 여기에 등록을 빠뜨린 것이다.

## 이번 단계에 쓴 문법 — 빠른 참조

| 문법 | 하는 일 | 예시 |
| --- | --- | --- |
| `@Module({...})` | 이 클래스가 모듈임을 표시하고, 소속 컨트롤러·서비스를 Nest에 등록 | `@Module({ controllers: [AppController] })` |
| `@Controller()` | 이 클래스가 HTTP 요청을 받는 창구임을 표시. 괄호 안 문자열은 URL 앞부분 | `@Controller('reading-records')` → `/reading-records` |
| `@Get()` | 이 메서드가 GET 요청을 처리 | `@Get()` → `GET /` |
| `@Injectable()` | 이 클래스를 Nest가 만들어서 다른 곳에 주입해도 된다는 표시 | `@Injectable() export class AppService {}` |
| `private readonly x: T` (생성자 인자) | Nest가 `T`를 만들어 넣어주고, 동시에 클래스 속성으로 저장 | `constructor(private readonly appService: AppService) {}` |
| `void 함수()` | 반환된 Promise를 기다리지 않고 의도적으로 버린다는 표시 | `void bootstrap();` |

> `readonly`는 "한 번 정해지면 다시 대입할 수 없다"는 TypeScript 표시다.
> 실수로 `this.appService = ...`처럼 바꿔치기하는 걸 컴파일 시점에 막아준다.
