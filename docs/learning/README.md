## 무엇을 적는가

노트는 **성격이 다른 두 가지**를 담습니다. 목적이 다르니 쓰는 방식도 다릅니다.

### 1. 빠른 참조 — 짧게

`@IsString()`이 무엇인지, `ParseIntPipe`가 왜 필요한지 같은 **문법과 API 설명**입니다.
아직 익숙하지 않은 것들이라, 노트를 다시 펼쳤을 때 검색 없이 바로 읽히려면 이게 있어야 합니다.

단, **한 줄 설명 + 예시 한 줄**로 제한합니다. 이 분량을 지키지 않으면
노트가 공식 문서를 베낀 열화판이 되고, 그러면 차라리 공식 문서를 보는 게 낫습니다.

```markdown
| `@IsOptional()` | 값이 없으면 나머지 검증을 건너뜀 | `@IsOptional() title?: string` |
```

**그 단계에서 실제로 쓴 것만** 적습니다. 안 써본 걸 미리 정리하면 기억에 남지 않습니다.

### 2. 막혔던 지점 — 길어도 됨

**검색해도 안 나오는 것.** 노트에서 가장 값진 부분입니다.

- 어떤 에러가 났고, 원인이 무엇이었고, 어떻게 알아냈는지
- 왜 A 대신 B를 골랐는지 (예: 왜 `new`로 서비스를 만들지 않기로 했는지)
- 예상과 실제가 달랐던 지점

이 섹션에 쓸 내용이 없는 노트는 사실 배운 게 별로 없는 단계였다는 뜻입니다.

> 요약하면 — **참조는 짧게, 겪은 일은 자세히.**

## 커밋 해시를 함께 적는 이유

각 노트에는 관련 커밋 해시가 있습니다. 글로 설명이 부족하면 코드를 직접 꺼내볼 수 있습니다.

```bash
git show 4e82ad9              # 그 단계에서 바뀐 코드 전체
git show 4e82ad9 --stat       # 어떤 파일이 바뀌었는지만
```

## 새 노트 템플릿

````markdown

- 관련 커밋: `해시`

## 이번 단계에 쓴 문법 — 빠른 참조

| --- | --- | --- |
| | 한 줄로 | 한 줄로 |

에러 메시지, 원인, 어떻게 알아냈는지. 이 섹션이 제일 중요함.

```
````
